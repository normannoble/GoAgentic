# Agents in T3 Code

T3 Code is a desktop and web app that runs coding agents (Claude Code, Codex and others) as **threads** in a sidebar. It plays the part Herdr plays in a terminal: it shows who is live and lets one agent start another where {{PRINCIPAL}} can watch it. This file maps the Herdr mechanics in `reference/peer.md` and `reference/task.md` onto T3. Everything else (the files, statuses, rounds, timeboxes, autonomy) is the same.

## Detecting it

Every T3 session carries `T3CODE_CLI_PATH`, the path of the `t3` command-line tool. Run `echo "HERDR_ENV=$HERDR_ENV T3=$T3CODE_CLI_PATH"` (you cannot see env vars otherwise):

| Echo shows | Host | Mechanics |
|---|---|---|
| `HERDR_ENV=1` | Herdr | `reference/peer.md`, `reference/task.md` as written. Herdr wins if both are set: an agent started in a Herdr pane is in Herdr |
| `HERDR_ENV=` and `T3=<path>` | T3 | this file |
| both empty | neither | `/agents:ask` and `/agents:delegate` refuse, as before |

The tool is not on `PATH`; always call it as `"$T3CODE_CLI_PATH"`. Run it from the workspace root: T3 resolves the project from the current directory.

## The map

| Herdr | T3 |
|---|---|
| A pane or tab named `<Name> - <title>` | A thread titled `<Name> - <title>` |
| `herdr agent rename`, `herdr pane rename`, `herdr tab rename` at startup | Rename this thread with T3's thread tool (`t3_thread_update`, `action: rename`; the MCP prefix differs per harness, for example `mcp__t3-code__`). If the tool is not available, skip silently |
| `herdr pane split` + `herdr agent start` + `herdr agent prompt` | `"$T3CODE_CLI_PATH" thread start . "<start> <target> task <file>" --title "<Target> - Task"` (or `- Peer`), which prints the new thread id |
| `herdr agent wait … --until idle --until done --until blocked` | `--wait` on the `thread start` or `thread send` call: it returns when the member ends its turn. Exit 0 = turn ended, 1 = the run failed, 2 = the member is waiting on an approval or a question in its thread |
| `herdr agent prompt <target>-task "Answered in <file>, continue."` | `"$T3CODE_CLI_PATH" thread send <thread id> "Answered in <file>, continue." --wait` |
| `herdr agent read <target>-task` | `"$T3CODE_CLI_PATH" thread show <thread id> --messages 3` |
| `herdr agent list` (who is live) | `"$T3CODE_CLI_PATH" thread list --json`: a thread other than your own whose `title` starts `<Name> - ` (case-insensitive) is live when it is a `<Name> - Peer` or `<Name> - Task` thread with `status: running`, or any other `<Name> - …` thread (a human session, `<Name> - <title>`) with `settled: false`. Peer and task threads stay unsettled after they finish, so for them only `running` counts; a human session is live while it is open, even between turns, as an idle Herdr pane is |
| `herdr pane close <id>` | Settle the thread (`t3_thread_organize`, `action: settle`, with its thread id; the MCP prefix differs per harness). It leaves the active list for the Settled list and stays readable as the record |
| `task_pane: <pane id>`, `lead_pane: <pane id>` | `task_pane: t3:<thread id>`, `lead_pane: t3` |

## Waiting

A `--wait` call blocks. For a task, which can run for hours, run it in the background (Claude Code: Bash with `run_in_background`) so the lead is woken when the member ends its turn, exactly as with `herdr agent wait`. For a peer request, run it in the foreground with a 10-minute timeout, as `/agents:ask` does in Herdr.

**The member ends its turn; it never sleeps.** In T3 a member that needs an answer, or is done, writes the work order and ends its turn: that is what returns the lead's `--wait`. A member must not hold its turn open with a sleep loop waiting for the lead or for a long job; T3 shows it as running and the lead is never woken. If it is waiting on something external (a deploy, a CI run), it logs that in the work order and ends its turn; the lead prompts it again.

## What T3 does not have

- **Side-by-side panes.** A member opens as its own thread in the sidebar, not beside the lead. `herdr pane layout` has no equivalent and is skipped.
- **The dashboard.** `goagentic dash` and its key binding are Herdr plugins. In T3, `/agents:status` is the board.
- **Approval prompts in another thread.** Exit code 2 means the member is waiting in its own thread. Never answer it from the lead; tell {{PRINCIPAL}} which thread and what it asks, as with `blocked` in Herdr.
